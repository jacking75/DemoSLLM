## A안 구현·추천안 후속 보완 — 2026-09-30

사용자는 외곽 코드블록 정규화 A안을 승인하고 앞으로 일반적인 구현 선택은 추천안으로 진행하라고 요청했다. 일반 기술 선택 때문에 결정을 재질문하지 않되, 안전 범위 확대·파괴적인 외부 작업 권한으로 해석하지 않는다. 게이트는 실제 결과를 보고한 뒤에만 다음 단계로 진행하며 미확인과 실패를 통과로 바꾸지 않는다.

`ModelJson.ParseObject`는 응답 전체가 단일 `json` 또는 무언어 코드블록이면 외곽만 제거한다. 앞뒤 설명·다중 객체·다중 블록·부분 JSON은 거부한다. `answer`/`citations` 두 필드와 숫자형 출처·검색 후보 내 번호 검증을 유지하고 중복 필드도 거부한다. 실패 원문은 `VaultResponseException.Raw`와 진단 질문별 JSON에 보존한다. 문자열 출처를 숫자로 임의 변환하지 않는다.

### GUI 시작 조건과 남은 작업

재측정 후 self-contained GUI PID 57092를 실행해 시작 버튼을 눌렀다. 기존 정책의 `여유 VRAM < 6,000,000,000 bytes` 조건으로 **VRAM 폴백 확인**이 나타났다. 모델이나 임계치를 바꾸는 도구 호출은 하지 않았다. 이후 상태 확인에서는 서버 PID 55968·컨텍스트 4096, 즉 E2B 폴백 상태가 관측됐다. 폴백 확인 버튼을 누른 주체는 미확인이다. [GUI 상태 증거](stage2-runs/20260930-192817-3e72f8/gui-model-mismatch.json)를 보존하고 이 실행은 E4B 유지 A안의 GUI 통과 증거에서 제외했다. 이 GUI에서 A/B/F 추론을 진행하지 않았다.

시험 앱은 정상 닫기 요청으로 종료했고 후속 프로세스 조회에서 `LocalMindStudio.exe`와 `llama-server.exe`가 없음을 확인했다. 종료 후 2026-09-30 19:33:59 KST NVML은 총 8,585,740,288 bytes·사용 2,641,059,840 bytes·여유 **5,944,680,448 bytes**였다. 6GB 시작 기준까지 약 55.32MB가 부족하다. 미래 시작 시 필요한 추가 여유는 변동하므로 이 차이만 확보하면 항상 시작한다고 보장하지 않는다.

다음 대안은 사용자 결정·조치가 필요하다.

1. **A 유지 (권장):** 사용자가 브라우저·Steam 등 사용 중인 VRAM 소비 프로그램을 직접 정리한 뒤, 여유 6GB 이상을 다시 확인하고 E4B GUI를 검증한다. 다른 프로그램의 개별 VRAM 기여는 미확인이다. 임계치·모델·7GiB 상한을 유지한다.
2. **B로 별도 변경 승인:** E2B·4K 폴백을 데모 기준으로 선택하고 품질·VRAM·GUI를 다시 검증한다. 이번 A 선택을 B 승인으로 해석하지 않는다.

GUI 시작 임계치를 낮추는 변경은 자동 수행하지 않는다. E4B GUI·PDF/DOCX 정상 입력·두 서버 강제 종료 등 남은 검증 완료 전 전체 게이트 통과·3단계 시작을 하지 않는다.

Publish 빌드는 경고 0개·오류 0개이다. [빌드 로그](stage2-build.log)가 근거이다. 빌드는 기능 수용·게이트 통과와 다르다. 현재 실행 파일은 `src/App.Wpf/bin/x64/Debug/net10.0-windows/win-x64/publish/LocalMindStudio.exe`이다.

## 구현 범위와 미확인

이미지 파일 드롭·붙여넣기·주 모니터 영역 선택, 설명·진단·고정 JSON 추출, DataGrid, 확인 후 CSV 저장을 연결했다. JSON 파싱 실패는 최대 2회 재시도하고 실패 결과는 저장하지 않는다. CSV 항목명 수식 주입을 막는다. 폴더의 최상위 지원 문서 1~100개를 읽고 800자 상한·100자 중첩 청킹, CPU 임베딩, SQLite 트랜잭션 교체, 코사인 Top5 검색을 구현했다. 답변에 인용된 파일명·문단 번호·원문 청크를 표시한다. 문서 링크·20MiB 초과 파일·5000청크 초과 색인은 거부한다.

[모의 검증 결과](stage2-runs/selftest-20260930-180916/result.json)는 14항목 통과이다. 이미지 순서, 빈 이미지 거부, JSON 재시도 상한, 잘못된 숫자/빈 행, CSV 수식, 청크 중첩, 코사인, SQLite 저장·조회, 취소 시 기존 색인 유지, 허위 출처 번호, 근거 없음, TXT/MD 읽기를 검사했다. PDF/DOCX 정상 입력·스캔 PDF 거부·긴 실제 문서의 문단 번호·GUI 드롭/클립보드/영역 캡처/CSV 조작·두 서버 강제 종료는 이번 단계에서 아직 미확인이다. 아이디어 카드 문구는 초안이며 사용자 승인으로 간주하지 않는다.

PdfPig는 공식 권장 추출 방식인 `ContentOrderTextExtractor`를 사용했다. [PdfPig 공식 문서](https://github.com/UglyToad/PdfPig)를 확인한 agent-reach 자료 확인 절차가 파서 선택에 반영됐다. 문서·이미지·추론 입력은 외부 자료 확인에 사용하지 않았다. C/D는 P2 보류이며 E는 아직 구현하지 않는다.

## 최초 제시 대안 — 사용자가 A 선택

**A — 현재 E4B·8K 설정 유지, 데모 환경 정리 후 재측정 (권장).** 사용자가 다른 VRAM 사용 프로그램을 정리한 후 같은 고정 문서·질문으로 재측정한다. 상한과 모델을 유지한다. 이 환경에서 재측정도 상한을 넘을 가능성은 미확인이다. 다른 프로그램을 자동 종료하지 않는다.

**B — 기존 E2B·4K 폴백으로 2단계 전체 재검증.** 메모리 여유를 확보할 수 있지만 E2B의 이미지·RAG·F 품질은 이번에 아직 검증하지 않았다. 사용자 선택 후 동일 A 샘플 3종·B 질문 10개·F 3종·GUI·동시 서버 VRAM을 다시 측정하고 기본 데모 모델 변경안도 문서에 명시한다. 설정을 미리 바꾸지 않는다.

사용자는 A를 선택했다. 상한·설정은 유지했으며 재측정 결과는 위 A안 절에 기록했다. 7GiB 상한을 올리거나 관측값을 빼는 변경은 하지 않는다.
