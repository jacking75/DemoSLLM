## 현재 결론

**E 구현과 팝업 자체 검사는 완료했으나 3단계 게이트는 미통과이다.** 검사 스크립트의 실제 `SendInput`은 `0/2·구조체 크기 40·Win32 5(접근 거부)`로 실패했다. 메모장·브라우저에서 실제 선택을 읽었다고 주장하지 않는다. 단축키 예약과 가짜 팝업의 모델 응답은 확인했지만 시스템 전체 동작의 대체 증거가 아니다. 4단계는 시작하지 않는다.

2단계는 [최신 GUI](stage2-runs/20260930-232936-gui-447f35/result.json)의 A 3/3·영수증 9000·B 출처 10/10·F 3종·5.157009GiB·두 서버 종료, 실제 캡처·CSV 저장·표 가독성을 보고한 뒤 통과했다. 그 이전 실패를 지우거나 상한·샘플·통과 기준을 바꾸지 않았다.

## E 구현 범위

`RegisterHotKey`로 Ctrl+Alt+Space와 반복 금지를 등록한다. 충돌하면 등록 실패를 표시하고 다른 앱의 단축키를 제거하지 않는다. 종료 시 등록과 트레이 자원을 해제한다. 원래 입력 창의 포커스를 기억하고 사용자가 단축키를 놓기까지 기다린다. 명시적 단축키에만 `SendInput` Ctrl+C를 보낸다. 클립보드 순번 변화를 기다려 선택 텍스트만 읽고 원래 데이터를 복원한다. 포커스·클립보드 변경·빈 선택·2000자 초과·형식 읽기 실패는 성공 결과로 사용하지 않는다. 모델은 E2B·4K이며 사고 모드 해제는 기존 서버 요청 설정을 그대로 사용하고 출력은 384토큰·temperature 0.2로 제한한다.

팝업은 요약·맞춤법 교정·정중한 어투·영어 번역을 제공하고 실제 SSE 응답을 표시한다. 원래 앱에 결과를 자동 입력하지 않는다. 취소·종료는 진행 중 요청에 전달한다. 창 최소화 시 트레이에서 계속 실행하고 트레이 메뉴에서 복원·명시적 종료할 수 있도록 구현했다. 트레이 메뉴를 실제로 클릭한 사용자 조작과 모든 입력 앱의 호환성은 미확인이다.

## 검사 환경과 클립보드 보호

Windows PowerShell의 클립보드 검사에서 `EnterpriseDataProtectionId`가 `CLIPBRD_E_BAD_DATA`로 실패했다. [앱 .NET 10 읽기 전용 검사](stage3-runs/clipboard-probe-20260930-235540/result.json)에서는 예외가 나지 않았다. 다만 최초 probe는 반환값 null도 성공으로 세던 검사였다. 현재 probe는 null 여부를 구분하며 `ShortcutClipboard.Snapshot`은 선언된 형식 값이 null이면 복사를 시작하지 않는다. 보호 표식이나 읽기 불가능한 형식을 임의로 제외하지 않는다. 해당 형식의 실제 정책 의미·최초 클립보드 메타데이터의 완전 동일 복원은 **미확인**이다. 초기 검사에서 값이 null인 형식을 복원 목록에서 제외할 수 있던 코드는 수정했다.

진단용 .NET 10 보조 프로세스는 읽을 수 있는 원래 클립보드를 메모리에만 보관하고 종료 순번이 맞을 때 복원한다. 원래 클립보드 내용은 파일에 쓰지 않는다. 첫 가드 검사에서는 신호 파일 쓰기·읽기 경합이 발생했다. 현재는 임시 신호를 완성한 뒤 원자적으로 공개한다. [후속 가드 결과](stage3-runs/20261001-000444-e5bce5/guard-result.json)는 복원 호출 성공·오류 null이지만 당시 보관 형식은 Text/UnicodeText이며 모든 메타데이터 동일성을 증명하지 않는다. 클립보드가 새 작업으로 변경됐거나 종료 신호가 없으면 임의로 덮어쓰지 않고 미완료를 기록한다.

첫 [시스템 검사](stage3-runs/20260930-235909-ab3094/result.json)는 포커스 실패, 다음 [검사](stage3-runs/20261001-000104-792e9a/result.json)는 키 입력 실패, 마지막 검사도 Win32 5로 실패했다. 세션은 Active로 표시된 시점도 있었다. 이는 Active 표기만으로 모든 입력 권한이 충족되지 않음을 보여주며, 앱 프로세스의 Ctrl+C가 동일하게 실패한다고 확정한 것은 아니다. 로그인·권한·UIPI·보안 설정을 변경하지 않았다.

브라우저 검증 준비에는 playwright-cli 스킬을 사용해 별도 메모리 프로필의 Edge 세션만 만들었다. `file:` 탐색은 도구에서 차단됐고 루프백 탐색도 완료되지 않았다. 가짜 HTML을 about:blank에 직접 준비하고 `bringToFront`로 실제 시험 창을 확인했다. 외부 페이지나 사용자 브라우저 프로필은 읽지 않았고 실제 브라우저 선택 검증은 미확인이다. 보조 루프백 서버는 종료했다.

## 충돌과 다음 검증

명세는 메모장과 브라우저에서 실제 단축키가 동작해야 한다. 현재 에이전트 검사 프로세스는 실제 입력 호출이 접근 거부되므로 그 게이트를 측정하지 못했다.

- A 권장: 잠금 해제된 사용자 데스크톱의 일반 PowerShell에서 동일 검사를 실행한다. 권한을 높이거나 보안 설정을 바꾸지 않으며 실제 결과를 붙여 넣어 판정한다.
- B: 시스템 입력 검증과 3단계를 보류한다. E를 통과했다고 소개하지 않으며 4단계를 시작하지 않는다.

향후 일반 선택을 추천안으로 진행하라는 사용자 요청에 따라 A를 추천한다. 그러나 사용자 데스크톱 실행 권한을 새로 확보하거나 접속·잠금을 임의로 변경하지 않는다. 현재는 환경 조건 때문에 보류이다.

```powershell
Set-Location C:\WorkingDev\DemoSLLM
# 별도 가짜 브라우저 준비
playwright-cli -s=localmind-stage3 open --browser=msedge --headed
playwright-cli -s=localmind-stage3 run-code --filename=tools/stage3-browser-fixture.js
& tools/Test-Stage3.ps1
# 직접 띄운 이름 지정 세션만 닫는다
playwright-cli -s=localmind-stage3 close
```

검사 중에는 데스크톱 연결·잠금 해제를 유지하고 다른 앱의 입력·클립보드 조작을 하지 않아야 한다. 스크립트는 새 가짜 TXT와 입력란만 사용하고 원래 앱에 AI 결과를 자동 붙여넣지 않는다. `result.json`에 실제 선택 원문 일치·클립보드 표본 복원·8개 변환·트레이 단축키·서버 종료가 기록돼야 한다. 이 결과와 화면을 확인한 뒤에만 3단계를 통과시킬 수 있다. 경영진 품질 수용·모든 클립보드 형식·4단계 7분 초심자 진행은 계속 미확인이다.
