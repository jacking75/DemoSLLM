5절 기본 모델은 이번 입력에서 더 빠르고 VRAM이 낮은 Google QAT와 같은 저장소의 프로젝터를 채택하는 안이다. 사고 출력은 QAT 0/57, ggml-org 1/57이며 영구 비활성화 보장으로 표현하지 않는다.

## 충돌과 대안 두 가지

사고 off 의도와 ggml-org의 응답이 충돌했다. 오류 이미지 답변이 잘렸고 실제 사용자 음성 평가가 없다. 512 출력 토큰은 스파이크 설정이지 명세 필수 제한은 아니다. 도구 수용 임계값은 명세에 없어 임의로 만들지 않는다.

- A: C/D 검증을 유지한다. 사용자 녹음 5개·수용 평가를 확보하고, 오류 답변 형식/출력 예산과 도구 확장자 스키마를 보완해 동일 입력을 재측정한다. 필요하면 ggml-org 사고 제어도 보완 측정한다. 그 뒤 채택·강등과 게이트를 결정한다.
- B: 경영진 데모 범위를 줄인다. Google QAT를 채택하고 C(음성)·D(파일 정리)를 P2로 보류한다. 오류 이미지 답변을 짧은 원인·조치 형식으로 보완하고 VRAM·답변 완결성을 재측정한다. 게이트 결과를 보고해 통과한 뒤 1단계를 진행한다. C/D는 추후 별도 검증·승인 후 복귀한다.

사용자가 후속 B를 승인했다. Google QAT 채택과 C/D P2 보류를 반영하고 오류 이미지 보완 실측 후 0단계 게이트를 보고한다. 통과 보고 후에만 1단계를 진행한다. 실제 사용자 음성 품질과 실제 파일 작업은 미확인으로 유지한다.
